# Testing and QA

Every QA requirement (C01–C25, R01–R20, A01–A30, P01–P12, V01–V20, G01–G20, T01–T15,
CLOUD01–CLOUD20, SEC01–SEC10, F01–F20, S01–S10, N01–N09; 211 IDs in all) is registered in
[`tests/requirements.py`](tests/requirements.py). Each test declares the IDs it proves with
`@pytest.mark.req(...)`.

A pytest hook writes the outcome of every ID to `reports/requirements.json` and
`reports/TEST_REPORT.md`:
- **PASS:** every mapped test ran and passed.
- **FAIL:** any mapped test failed.
- **NOT RUN:** no test executed it. An untested ID can never show as PASS.
- **Live-cloud IDs** take their status only from real GitHub run URLs in
  [`tests/live_evidence.json`](tests/live_evidence.json), never from local tests.

## Commands

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt -r requirements.txt
.venv/bin/python -m pytest -q --junitxml=reports/junit.xml   # everything (~4 min); JUnit + requirement matrix
.venv/bin/python -m pytest -q -m "not slow" tests/test_qa_source.py   # one subsystem
.venv/bin/python -m quizbot evaluate                           # practice regression, 1,200 keyed questions
.venv/bin/python -m tests.simulate_week --hours 120            # full graded-week rehearsal (~15 min)
GITHUB_TOKEN=$(gh auth token) .venv/bin/python -m quizbot audit --repo mapledang/dso429-hourly-quiz
```

## Test levels

| Level | Where | What it proves |
|---|---|---|
| unit | `test_qa_source.py`, `test_qa_solver.py`, `test_qa_practice_output.py` | parsing, solving, validation in isolation |
| integration | HTTP retry with fake openers; git with a real temporary bare repository | plumbing under injected faults |
| e2e | `test_qa_reconcile.py`, `test_qa_git.py`, `test_qa_failures_e2e.py`, `test_qa_audit.py` | the whole pipeline against a temporary remote, with fixed clocks |
| regression | official `questions.csv` and `practice_keys.csv` (fixtures) | 1,200/1,200 practice accuracy; evaluator self-checks |
| fuzz | `test_fuzz.py` | 5,200 random questions against an independent Decimal reference (mutation-tested) |
| static | workflow YAML, cron cadence, pinning, permissions | configuration correctness |
| simulation | `tests/simulate_week.py` (12h in CI, 24h in pytest, 120h on demand) | dropped and delayed runs, outages, lag, push failures, graded by the assignment's rules |
| live | real GitHub Actions runs (`live_evidence.json`) | cloud execution and recovery |

## Safety rules the tests follow

- Tests never touch the real repository. Git tests use `tmp_path` bare remotes. Production mode
  refuses to run outside GitHub Actions, with a simulated clock, or in any repository other than
  `mapledang/dso429-hourly-quiz`.
- The system clock is never changed. `QUIZ_NOW` fixes the clock for tests and simulations.
- No live credentials are needed. Claude backends are scripted fakes; the network is a fake
  opener.
- Expected answers are hand-derived (with the arithmetic shown) or taken from the official keys.
  They are never generated by the solver under test.

## Known limitations (no test can remove these)

- Passing the practice benchmark does not guarantee accuracy on unseen graded wording. Unfamiliar
  questions go to Claude, if a credential secret is configured, or to a flagged guess with an
  alert email.
- Passing cloud runs do not guarantee future scheduled runs. Mitigations: cron, the
  `keepalive` chain that doesn't depend on cron, the hourly reconcile, and the watchdog.
- "Laptop powered off" was not physically tested. The evidence is that runs are started by
  GitHub itself (keepalive and scheduled events) and execute on GitHub-hosted runners.
